# REAREye 仓库组件 / 主题校验规范

> 本文档整理 REAREye 背屏组件仓库（RearStore）在**安装组件（卡片）与壁纸（主题）**时的校验核对规则，
> 供制作、提交主题 / 组件时参考，避免因格式或依赖不满足导致安装失败。
>
> 所有规则均来自当前客户端实现（`hk.uwu.reareye.repository.rearstore` 与
> `hk.uwu.reareye.repository.rearwallpaper`、`hk.uwu.reareye.hook.scopes.subscreencenter`）。

---

## 1. 两种安装模式

仓库支持两种组件形态，由 `widget_info.type` 决定：

| `type` 值 | 模式 | 说明 |
| --- | --- | --- |
| `widget` | 组件模式（卡片） | 安装为背屏组件（business），可附带常驻卡片与通知路由 |
| `wallpaper` | 壁纸模式（主题） | 安装为背屏壁纸资源（.mrc / .zip 包） |

- `type` 缺省或无法识别时，按 `widget` 处理。
- 元数据类型 `metadata.type` 另有细分：`card`（卡片）、`notification`（通知）、`enhanced`（增强）、`wallpaper`（壁纸）、其他 → `unknown`。

---

## 2. 安装校验流程（顺序）

`quickInstallWidget` 依次执行以下校验，任一不通过即抛出错误并终止安装：

1. **安装模式支持检查** — `supportedInCurrentVersion`
2. **模块版本检查** — `supportsModuleVersion()`
3. **依赖要求检查** — `evaluateRequirements()`（应用包名 + 模块配置）
4. **冲突检查** — `resolveInstallConflict()`（仅组件模式）
5. **资源选择与下载** — `prepareInstallAsset()`
6. **实际安装** — 组件写入 / 壁纸导入

> 第 4 步冲突时，UI 会先弹出“覆盖 / 卸载”确认；只有确认后才携带 `forceOverwrite` 再次进入。

---

## 3. widget_info 结构

仓库为每个组件 / 每个 Release 提供 `widget_info` 对象（字段同时兼容下划线与驼峰写法）：

```jsonc
{
  "type": "widget",                 // "widget" | "wallpaper"
  "name": "组件名称",
  "business_setup": {               // 组件模式必需
    "id": "业务唯一标识",           // 必填，否则安装报错
    "renameable": true
  },
  "card_setup": {                   // 组件模式可选，附带常驻卡片
    "name": "卡片标题",
    "package": "目标包名",
    "priority": 500,                // 默认 500
    "sticky": true,                 // 默认 true
    "renameable": true
  },
  "scene_setup": {                  // 组件模式可选，附带通知路由
    "scene": "场景名",
    "pkg": "路由包名"               // 兼容 "package" / "packageName"
  },
  "min_version": -1,                // 最低模块版本（-1 表示不限制）
  "max_version": -1,                // 最高模块版本（-1 表示不限制）
  "requirements": {                 // 可选，依赖要求
    "packages": ["com.example.app"],
    "configs": { "模块配置键": "== true" }
  },
  "postinstall": { "uri": "..." }   // 可选，安装后跳转链接
}
```

字段映射（`@SerializedName`）：

| JSON 字段（兼容写法） | 含义 | 默认值 |
| --- | --- | --- |
| `type` | 组件 / 壁纸类型 | `widget` |
| `name` | 组件名 | 空 |
| `business_setup` / `businessSetup` | 组件业务配置 | `null` |
| `card_setup` / `cardSetup` | 附带卡片配置 | `null` |
| `scene_setup` / `sceneSetup` | 通知路由配置 | `null` |
| `minVersion` / `min_version` | 最低模块版本 | `-1` |
| `maxVersion` / `max_version` | 最高模块版本 | `-1` |
| `requirements` | 依赖要求 | `null` |
| `postinstall` | 安装后跳转 | `null` |

## 4. 模块版本检查

- 使用模块自身的 `VERSION_CODE`（`BuildConfig.VERSION_CODE`）与组件声明比较。
- 规则：`minVersion <= 当前版本 <= maxVersion`。
- `-1`（`WIDGET_VERSION_CHECK_DISABLED`）表示该侧不限制。

不满足时报错：**“当前模块版本不支持安装该组件”**。

---

## 5. 依赖要求（requirements）

### 5.1 应用包名（packages）

- `packages` 为字符串数组，逐个校验是否已安装。
- 校验依赖 `com.android.permission.GET_INSTALLED_APPS`（“已安装应用列表”权限）。
- 若未授予该权限且声明了 packages，直接报错：**“校验组件依赖应用需要已授予应用列表权限”**。
- 缺包报错：**“缺少依赖应用：包名1, 包名2”**。

### 5.2 模块配置（configs）

- `configs` 为 `{ 配置键: 表达式 }` 映射。
- **配置键**必须对应 REAREye 内部配置项（`ConfigKeys` 中的常量，如 `enable_music_controls_whitelist_hook` 等）；未知键报错：**“未知配置：<key>”**。
- JSON 值为**布尔 / 数字**时自动转为 `== 值`；为**字符串**时作为表达式原文；为 `null` 或数组时忽略。

#### 表达式运算符

按长度优先解析，无运算符时按 `==` 处理：

| 运算符 | 含义 | 适用值类型 |
| --- | --- | --- |
| `>=` | 大于等于 | 数值 |
| `<=` | 小于等于 | 数值 |
| `==` | 等于 / 集合包含 | 布尔、数值、字符串、集合 |
| `!=` | 不等于 / 集合不包含 | 布尔、数值、字符串、集合 |
| `>` | 大于 | 数值 |
| `<` | 小于 | 数值 |

示例：

```jsonc
{
  "enable_music_controls_whitelist_hook": "== true",   // 布尔：需开启
  "unmute_video_wallpaper_volume": ">= 50",            // 数值：需 >= 50
  "music_controls_whitelist_apps": "== com.example.app" // 集合：需包含该应用
}
```

#### 值类型匹配规则

客户端根据**当前配置的实际类型**分发校验：

- **布尔**：`== true` / `== false` / `!= true` / `!= false`（其它运算符视为不满足）。
- **数值**（Int/Long/Float/Double）：支持 `>= <= == != > <`，操作数解析为数字。
- **集合 / 数组**：`==` 表示“包含”，`!=` 表示“不包含”。
- **字符串**：`==` / `!=` 做字符串比较。

## 6. 冲突校验（仅组件模式）

对组件（`widget`）安装，会检查是否与已有业务（business）冲突：

| 冲突类型 | 触发条件 | 提示 |
| --- | --- | --- |
| `SAME_WIDGET` | 同一仓库组件已安装 | 组件已安装，是否覆盖 |
| `MANUAL_BUSINESS` | 该业务 ID 已存在（手动创建，路由包为 `com.xiaomi.subscreencenter`） | 组件已存在，是否覆盖注册 |
| `OTHER_STORE_WIDGET` | 业务 ID 已被其它仓库组件注册 | 已被其它组件注册，需先卸载或强制覆盖 |

> 壁纸模式不参与冲突检查（按 widgetId 直接更新 / 新建记录）。

## 7. 资源选择与下载

- 优先选择指定 Release（按 `tagName`），否则选择**第一个含资源的 Release**。
- 在 Release 内优先指定资源名，否则按优先级选最优资源：

| 优先级 | 扩展名 |
| --- | --- |
| 0（最高） | `.mrc` |
| 1 | `.zip` |
| 2 | 其它 |

- 下载优先走仓库 API 资源地址，失败回退到资源的 `downloadUrl`。
- 无可用资源报错：**“未找到可下载的发布资源”**；下载失败报错：**“组件资源下载失败”**。

## 8. 壁纸（主题）包格式

### 8.1 支持的包类型

- 仅支持 `.mrc` 与 `.zip` 扩展名的壁纸包。
- 其它扩展名报错：**“仅支持 .mrc 或 .zip 格式的壁纸包”**。

### 8.2 内嵌元数据 metadata.mrm

壁纸包**根目录**可放一个 `metadata.mrm`（JSON 文本），用于覆盖壁纸标题 / 描述等：

```jsonc
{
  "authors":    { "fallback": "作者", "zh_CN": "作者" },
  "designers":  { "fallback": "设计者", "zh_CN": "设计者" },
  "titles":     { "fallback": "标题", "zh_CN": "标题" },
  "descriptions": { "fallback": "描述", "zh_CN": "描述" },
  "subResourceType": "分类",
  "resSubType": "资源子类型",
  "isRearScreenEditable": false,
  "isThirdParties": true,
  "supportAon": false
}
```

- `subResourceType` 等价于 `category`；`widgetCategory` 也可作为分类回退。
- 若包内存在名为 `not_editable` 的文件或目录，则该壁纸标记为**不可编辑元数据**。

### 8.3 壁纸安装流程

- 若目标 widgetId 已有壁纸记录，优先**更新**原壁纸；否则**导入**新壁纸。
- 更新遇到“壁纸不在运行时列表 / 不在当前列表”等软错误时，自动回退为导入。
- 只能编辑 / 更新 / 删除 / 生成预览**由 REAREye 导入的壁纸**，否则报错。

## 9. 常见报错与规避

| 报错提示（中文） | 原因 | 规避建议 |
| --- | --- | --- |
| 当前版本不支持…安装模式 | 组件声明的 `type` 不被当前版本支持 | 使用 `widget` 或 `wallpaper` 之一 |
| 当前模块版本不支持安装该组件 | `minVersion` / `maxVersion` 不匹配 | 正确填写版本区间，或用 `-1` 表示不限制 |
| 校验组件依赖应用需要已授予应用列表权限 | 声明了 packages 但未授予“已安装应用列表”权限 | 引导用户授予该权限，或去掉 packages |
| 缺少依赖应用：… | 依赖应用未安装 | 移除不必要依赖，或在说明中注明依赖 |
| 配置要求未满足：… / 未知配置：… | `requirements.configs` 引用了不存在或不满足的配置 | 使用真实配置键与正确表达式 |
| 组件缺少必需的 business_setup.id 配置 | 组件模式缺 `business_setup.id` | 为组件填写唯一 `business_setup.id` |
| 组件已安装 / 已存在 / 已被其它组件注册 | 业务 ID 冲突 | 使用唯一业务 ID，或走覆盖 / 卸载流程 |
| 未找到可下载的发布资源 / 组件资源下载失败 | Release 无资源或网络失败 | 确保 Release 附带 `.mrc` / `.zip` 资源 |
| 壁纸安装失败 / 组件资源保存失败 | 写入失败 | 检查存储空间与权限 |
| 仅支持 .mrc 或 .zip 格式的壁纸包 | 资源扩展名非法 | 打包为 `.mrc` 或 `.zip` |
| 背屏壁纸 Hook 服务未连接 / 背屏组件 API 服务未连接 | 模块未在目标进程生效 | 确认 LSPosed 作用域包含背屏中心并已重启 |

---

## 10. 附录：默认作用域与路由包

- 默认目标进程：`android`、`com.xiaomi.subscreencenter`、`com.android.thememanager`、`com.android.systemui`。
- 组件默认路由包：`com.xiaomi.subscreencenter`。
- 通知路由 `scene_setup.pkg` 缺省即该路由包；卡片 `card_setup.package` 需显式指定目标包名。
