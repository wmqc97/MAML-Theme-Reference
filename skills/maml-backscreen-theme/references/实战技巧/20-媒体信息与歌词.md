# MAML 背屏主题 · 媒体信息与歌词

> 作者：唯梦倾城 | 创建：2026-10-03（合并 2026-09-21 车机版实测 + 2026-10-03 手机版实测）
> 地位：音乐/歌词类背屏主题**权威参考**（歌名·歌手·歌词字段、双播放器场景与判别规则全在此）
> 关联：12 号（WebView 能力边界）、16 号（官方元素）、13 号（HTML 样板）
> 实测机型：小米 17 Pro Max 背屏（976×596，WebView 视口 348×212，dpr 2.8125）

## 一、结论先行（先看这 6 条）

1. **HTML/JS 拿不到 MediaSession**（12 号结论正确），但 **MAML 层拿得到**——`MusicController` 用
   `MediaSessionManager.addOnActiveSessionsChangedListener` 跟踪活动会话并注册成 MAML 变量。
   正确分工：**数据在 MAML，渲染在 HTML**（HTML 用 `window.maml.getXxx` 读）。
2. **歌词有两条完全不同的路**，取决于播放器：
   - **车机版**（`cn.kuwo.kwmusiccar`）：走 **LyricExportBroadcast 广播** → `line_text`
   - **手机版**（`cn.kuwo.player`）：**把歌词写进 `title` 字段滚动** → 只能按变化判别
3. **MediaSession 的 `LYRIC` 字段两家酷我都不写** → `lyric_*` 恒空，别指望它。
4. **歌名优先取 `artist`**——实测恒为 `歌名(版本)-歌手`，最稳。**不要用 `title` 当歌名**（可能正被歌词占用）。
5. **判据：歌名在一首歌内恒定，歌词会持续变化。** 用 `title` 变化频率区分。
6. **三通道合并 + 谁有值用谁**，单通道都会在某些播放器下失空。

## 二、三条数据通道（实测对照）

| # | 通道 | 写法 | 车机版 | 手机版 |
|---|------|------|--------|--------|
| ① | 系统全局变量 | `@musicName.title` / `#musicName.music_state` | ✅ | ⚠️ 全 0 |
| ② | **MusicControl 元素** | `<MusicControl name="mctl">` → `@mctl.title` | ✅ | ✅ **主力** |
| ③ | **酷我歌词广播** | `<BroadcastBinder action="...LYRIC_PROGRESS">` | ✅ | ⚠️ 无 |

## 四、MusicControl 元素

```xml
<!-- 不可见的数据源：无子元素、无按钮，只跟踪 MediaSession -->
<MusicControl name="mctl" x="0" y="0" w="10" h="10"
              autoShow="false" enableLyric="true" updateLyricInterval="50"
              visibility="false"/>
```

| 属性 | 说明 |
|------|------|
| `name` | 实例名，决定变量前缀 |
| `enableLyric` | **必须 true**，否则不解析歌词 |
| `updateLyricInterval` | 歌词刷新间隔（ms）。50 够用，越小越耗电 |
| `autoShow` | 自动显隐（背屏做数据源设 false） |
| `visibility="false"` | 隐藏自身，仅作数据源 |
| `defAlbumCover` / `clip` | 封面兜底图 / 裁剪 |

⚠️ 元素**不必放进 `<VariableBinders>`**，直接放 Widget 下即可。
⚠️ **宽高 ≥10**——尺寸过小可能不初始化（曾踩坑致进度不更新）。

### 内置播放控制按钮（MediaSession transport）

```xml
<MusicControl name="music_control">
  <Button name="music_prev">...</Button>   <!-- BTN_PREV -->
  <Button name="music_play">...</Button>   <!-- BTN_PLAY -->
  <Button name="music_pause">...</Button>  <!-- BTN_PAUSE -->
  <Button name="music_next">...</Button>   <!-- BTN_NEXT -->
</MusicControl>
```
⚠️ MusicControl 内部用固定 action 名 `readText_by_name`，若 WebView 也定义同名 action 可能冲突。

## 五、歌词获取 · 场景 A：酷我车机版（广播）

### 5.1 广播定义（反编译 `LyricExportBroadcast.java`）

```java
public static final String ACTION_LYRIC_FULL     = "cn.kuwo.kwmusiccar.action.LYRIC_FULL";
public static final String ACTION_LYRIC_PROGRESS = "cn.kuwo.kwmusiccar.action.LYRIC_PROGRESS";
// 发送: setFlags(0x1000003) [INCLUDE_STOPPED_PACKAGES|FLAG_BROADCAST]，setPackage(null) → 无包限定
```

### 5.2 LYRIC_PROGRESS（实时，播放每 tick 一次）

| extra | 类型 | 说明 |
|-------|------|------|
| `music_id` | long | 歌曲 ID |
| `title` | String | 歌名 |
| `artist` | String | 歌手 |
| `position_ms` | long | 进度毫秒 |
| `line_index` | int | 当前行索引 |
| **`line_text`** | String | **当前行歌词** |
| `line_progress` | int | 行内进度 0-100 |
| `is_lrcx` | boolean | 是否逐字歌词 |
| `playing` | boolean | 是否播放中 |
| `lyric_type` | String | LRC/LRCX/TXT |

### 5.3 LYRIC_FULL（切歌时一次）

| extra | 类型 | 说明 |
|-------|------|------|
| `music_id` / `title` / `artist` | — | 歌曲信息 |
| `duration_ms` | long | 时长 |
| `lines` | String[] | **完整歌词数组** |
| `line_times_ms` | int[] | 每行时间戳 |
| `has_word_timing` / `words_json` / `words_json_uri` | — | 逐字歌词 |

### 5.4 开关与权限（root 可开）

```bash
# 歌词导出开关（默认 true）
cat /data/user/0/cn.kuwo.kwmusiccar/shared_prefs/float_lyric_settings.xml
# 悬浮窗权限（FloatLyricService 依赖，必须）
appops set cn.kuwo.kwmusiccar SYSTEM_ALERT_WINDOW allow
# 拉起服务
am startservice -n cn.kuwo.kwmusiccar/cn.kuwo.kwmusiccar.floatlyric.FloatLyricService
```
⚠️ 进程需**前台播放**才发广播；force-stop 后需用户手动打开酷我。
⚠️ 广播日志 tag `LyrXprt`（`send-bc` = 已发出）。

### 5.5 MAML 监听（**必须放 `<VariableBinders>` 容器内**）

```xml
<VariableBinders>
  <BroadcastBinder action="cn.kuwo.kwmusiccar.action.LYRIC_PROGRESS">
    <Variable name="kwTitle" type="string" extra="title"/>
    <Variable name="kwArtist" type="string" extra="artist"/>
    <Variable name="kwPos" type="int" extra="position_ms"/>
    <Variable name="kwLineIndex" type="int" extra="line_index"/>
    <Variable name="kwLine" type="string" extra="line_text"/>
    <Variable name="kwPlaying" type="int" extra="playing"/>
  </BroadcastBinder>
  <BroadcastBinder action="cn.kuwo.kwmusiccar.action.LYRIC_FULL">
    <Variable name="kwDur" type="int" extra="duration_ms"/>
  </BroadcastBinder>
</VariableBinders>
```

**关键坑**（反编译 `VariableBinderManager` 确认）：
- `loadBinders()` 只遍历 **`<VariableBinders>` 容器的直接子节点**
- ❌ 写在 `<Widget>` 根级 → **不加载、广播收不到**（曾踩坑）
- ✅ 必须包进 `<VariableBinders>...</VariableBinders>`
- 变量进全局空间，HTML `getStringByName('kwLine')` 可读
- ⚠️ BroadcastBinder **只支持单值 extra**，读不了 `String[]` → **拿不到"下一行"**

### 5.6 三行歌词的能力边界

| 行 | 数据源 | 能否实现 |
|----|--------|---------|
| 当前行 | `kwLine`（PROGRESS 实时） | ✅ |
| 上一行 | 本地缓存（当前行变化时存旧值） | ✅ |
| 下一行 | 需 `lines[]` 数组（FULL） | ❌ 读不了数组 |

> **结论**：纯 MAML/HTML 下**三行歌词无法完整实现**（缺下一行数据源）。
> 要三行需换播放器（把 LYRIC 写入 MediaSession，如系统音乐/Poweramp），或用 MiRoot 歌词投影。

## 六、歌词获取 · 场景 B：酷我手机版（蓝牙歌词）

### 6.1 实测原始数据（真机连续快照，同一首歌）

```
title  : 举杯邀明月叫三两好友        ← 变化
title  : 就别管那么多踏马肆意挥霍    ← 变化
title  : 岁月不过是一场蹉跎          ← 变化
title  : 不必计较太多世俗的对与错    ← 变化
title  : 去看向阳花开满那山坡        ← 变化
artist : 踏马寻花向自由(雷鬼版)-超哥  ← 恒定 ✅
mcState=1   mcPos=148083   mcDur=179000   mcLyric=<空>
```

→ **`title` 在滚歌词，`artist` 是歌名，`lyric_*` 全空。**
→ 把 `title` 当歌名显示，界面就会「歌名一直变」——最易踩的坑。

### 6.2 反编译佐证

`cn.kuwo.player` 的 metadata key 列表**不含** `android.media.metadata.LYRIC`，
只有 `DISPLAY_DESCRIPTION` / `DISPLAY_TITLE` / `DISPLAY_SUBTITLE` 等
→ **证实它不写标准歌词字段**，歌词走 `title` 滚动。

### 6.3 判别算法（模式粘滞 + 频率判定）

```
歌名在一首歌内恒定；歌词持续变化。故统计 title 变化次数：
  title 变化 >= 2 次    → lyric 模式（永久粘滞，不每首重置）
  title 静止 > 15s      → standard 模式
  其它                  → unknown（识别中，用 artist 兜底）

取值：
  lyric / unknown 模式 → 歌名 = artist      （最稳，永不会显示到歌词）
  standard 模式        → 歌名 = title
  歌词                 → lyric 模式取 title；否则空
```

**三条要点（踩坑换来的）**：
1. **模式要跨歌曲粘滞，不能每首重置**。否则新歌开头 `unknown` 期间会把歌词当歌名显示 → 用户看到「歌名不稳」。
2. **歌名一律优先 `artist`**，不要用 `title`。
3. 判定完成前约 1~2 秒用 `artist` 兜底，**不要显示 `title`**。

参考实现：
```js
var votes=0, mode="unknown", lastTitle="", titleSince=0;
var STATIC_MS=15000;
function feed(title,playing){
  var now=Date.now(); if(!playing)return;
  if(title && title!==lastTitle){ if(lastTitle!=="")votes++; lastTitle=title; titleSince=now }
  if(!titleSince)titleSince=now;
  if(votes>=2) mode="lyric";                                    /* 永久粘滞 */
  else if(mode!=="lyric" && now-titleSince>STATIC_MS) mode="standard";
  return mode;
}
var lyricMode=(mode==="lyric");
var songName = (mode==="standard") ? (title||artist) : (artist||title);
var lyricText= lyricMode ? title : "";
```

## 七、MAML 侧最小可用写法（三通道合并）

```xml
<Widget version="2" frameRate="30" scaleByDensity="false" screenWidth="976" transparentSurface="true">

  <!-- ① 系统全局变量 -->
  <Var name="gTitle"  type="string" expression="@musicName.title"/>
  <Var name="gArtist" type="string" expression="@musicName.artist"/>
  <Var name="gState"  type="number" expression="#musicName.music_state"/>

  <!-- ② MusicControl（主力） -->
  <MusicControl name="mctl" x="0" y="0" w="10" h="10"
                autoShow="false" enableLyric="true" updateLyricInterval="50" visibility="false"/>
  <Var name="mcTitle"  type="string" expression="@mctl.title"/>
  <Var name="mcArtist" type="string" expression="@mctl.artist"/>
  <Var name="mcPos"    type="number" expression="#mctl.music_position"/>
  <Var name="mcDur"    type="number" expression="#mctl.music_duration"/>
  <Var name="mcState"  type="number" expression="#mctl.music_state"/>

  <!-- ③ 酷我广播（车机版） -->
  <VariableBinders>
    <BroadcastBinder action="cn.kuwo.kwmusiccar.action.LYRIC_PROGRESS">
      <Variable name="kwTitle" type="string" extra="title"/>
      <Variable name="kwArtist" type="string" extra="artist"/>
      <Variable name="kwPos" type="int" extra="position_ms"/>
      <Variable name="kwLine" type="string" extra="line_text"/>
      <Variable name="kwPlaying" type="int" extra="playing"/>
    </BroadcastBinder>
    <BroadcastBinder action="cn.kuwo.kwmusiccar.action.LYRIC_FULL">
      <Variable name="kwDur" type="int" extra="duration_ms"/>
    </BroadcastBinder>
  </VariableBinders>

  <!-- 合并：谁有值用谁 -->
  <Var name="mtTitle"  type="string" expression="ifelse(strIsEmpty(@mcTitle),ifelse(strIsEmpty(@gTitle),@kwTitle,@gTitle),@mcTitle)"/>
  <Var name="mtArtist" type="string" expression="ifelse(strIsEmpty(@mcArtist),ifelse(strIsEmpty(@gArtist),@kwArtist,@gArtist),@mcArtist)"/>
  <Var name="mtPlaying" type="number" expression="ifelse(eq(#mcState,1),1,ifelse(eq(#gState,1),1,ifelse(eq(#kwPlaying,1),1,0)))"/>
  <Var name="mtHasSong" type="number" expression="ifelse(strIsEmpty(@mtTitle),0,1)"/>

  <!-- 切页条件 -->
  <Var name="showLyrics" type="number" expression="(#mtPlaying * #mtHasSong)"/>

  <WebView name="wv" x="0" y="0" w="#view_width" h="#view_height"
           local="true" cachePage="true" visibility="#showLyrics" uri="web/lyrics.html">
    <Triggers>
      <Trigger action="music_prev"><IntentCommand action="com.android.music.musicservicecommand" broadcast="true">
        <Extra name="command" type="string" expression="'previous'"/></IntentCommand></Trigger>
      <Trigger action="music_playpause"><IntentCommand action="com.android.music.musicservicecommand" broadcast="true">
        <Extra name="command" type="string" expression="'togglepause'"/></IntentCommand></Trigger>
      <Trigger action="music_next"><IntentCommand action="com.android.music.musicservicecommand" broadcast="true">
        <Extra name="command" type="string" expression="'next'"/></IntentCommand></Trigger>
    </Triggers>
  </WebView>
</Widget>
```

**HTML 侧读数据**：
```js
function gs(n,d){try{var v=window.maml.getStringByName(n);
  return (v===null||v===undefined||v==="")?d:String(v)}catch(e){return d}}
function gn(n,d){try{var v=window.maml.getDoubleByName(n);
  return (v===null||v===undefined||isNaN(v))?d:v}catch(e){return d}}
```

**切换原理**：`visibility="#showLyrics"` + 静态 `uri`。
- 平时 `=0` → WebView 不显示不创建（web/ 也不解压）
- 播放 → `=1` → 创建并加载歌词页
- 停止 → `=0` → 自动回落主界面

> 💡 `uriExp` 按状态换**多个** HTML 也行（值变化自动重载），但每次整页 reload 会闪；单页 + HTML 内部切视图更顺。

## 八、诊断方法：不用肉眼读数（重要工作技巧）

**HTML 的 `console.log` 在背屏收不到**——`MamlWebChromeClient` 只重写了 `onProgressChanged`，
**没有 `onConsoleMessage`**（反编译核实）。调试别指望 logcat。

**方案：值写进 `localStorage`，root 直接读 WebView 的 leveldb。**

```js
/* HTML：值变化时落盘 */
try{ localStorage.setItem("dbg", JSON.stringify({ts:Date.now(),title:t,artist:a,state:st})) }catch(e){}
```

```bash
# shell：读出来（路径含空格；必须经 /proc/<pid>/root 进 mount namespace）
P=$(pidof com.xiaomi.subscreencenter)
D="/proc/$P/root/data/data/com.xiaomi.subscreencenter/app_webview/Default/Local Storage/leveldb"
for f in "$D"/*.log "$D"/*.ldb; do
  iconv -f UTF-16LE -t UTF-8 -c < "$f" 2>/dev/null | grep -ao '{"ts":[^}]*}'
done | tail -20
```

**三个坑**：
1. **必须经 `/proc/<pid>/root/`**——subscreencenter 在独立 mount namespace，直接 `/data/data/...` 会 `No such file or directory`。
2. **leveldb 存 UTF-16LE**——直接 grep 只见 `D:0` 残片，**中文必须 `iconv -f UTF-16LE`**。
3. **log 会轮转**（`.log` → `.ldb`），要遍历所有 `*.log` 和 `*.ldb`。

## 九、踩坑速查

| 坑 | 现象 | 对策 |
|----|------|------|
| **拿 `title` 当歌名** | 歌名一直变（其实是歌词） | 歌名优先 `artist` |
| **模式每首重置** | 新歌开头歌名跳变 | 模式**跨歌曲粘滞** |
| 只听 `lyric_*` | 歌词永远空 | 两家酷我都不写 LYRIC |
| 只用一个通道 | 某些播放器无数据 | **三通道合并** |
| 等 `musicName.*` | 手机版全 0 | 用 `MusicControl` 元素 |
| BroadcastBinder 收不到 | 写在根级 | 必须放 `<VariableBinders>` 容器 |
| MusicControl 尺寸太小 | 进度不更新 | `w/h ≥ 10` |
| 歌词显示"已关闭" | Hook 直装 var_config 开关未初始化 | HTML 歌词常开 |
| 旧版 musicservicecommand 无效 | 酷我不响应 | 用 MediaButton keyevent |
| 酷我 force-stop 后无广播 | FloatLyricService 需前台 | 重新打开酷我 |
| 期望 `console.log` | logcat 无输出 | 写 `localStorage` 再读 leveldb |
| 读 leveldb 报不存在 | 直接访问 `/data/data` | 经 `/proc/<pid>/root/` |
| grep 中文失败 | 只见 `D:0` | `iconv -f UTF-16LE` |
| 想三行歌词 | 缺"下一行"数据源 | 换播放器或 MiRoot 投影 |
| `uriExp` 多页切换 | 每次 reload 闪黑 | 单页 + `visibility` 切换 |
